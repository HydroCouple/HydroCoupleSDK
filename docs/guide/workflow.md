@page sdk_guide_workflow 4. Configure the workflow

`ModelInitializer` reads the composition, applies argument values and resolves connections through the host’s instance lookup. Check the result and message from `initializeFromFile(path, message)` before preparing the workflow. The serial example supplies its own catchment and channel instances. A plugin-backed host such as Composer also needs each instance’s component type so it can construct it. [Initializer API](https://github.com/HydroCouple/HydroCoupleSDK/blob/removing_qt/include/hydrocouplesdk/io/modelinitializer.h) · [Composition schema](https://github.com/HydroCouple/HydroCoupleSDK/blob/removing_qt/share/schema/composition-1.1.json)

`TimeSteppedWorkflow` builds a dependency schedule during preparation. For the example, the catchment runs before the channel so the channel can read the current reach inflows. Cyclic groups have a configurable iteration count. If your model requires convergence, specify and verify that condition for the coupled model. A pull-driven workflow instead starts from a trigger input and asks upstream providers for values. [Time-stepped workflow API](https://github.com/HydroCouple/HydroCoupleSDK/blob/removing_qt/include/hydrocouplesdk/component/timesteppedworkflow.h)
